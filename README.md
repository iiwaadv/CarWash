# CarWash Ops Engine (COE)

نظام تشغيلي وإداري ميداني لمغاسل السيارات — يغطي المرحلة الأولى (MVP) بالكامل مع قاعدة بيانات وواجهات برمجية جاهزة للمرحلتين الثانية والثالثة.

## 🧱 هيكلة المشروع

```
New folder/
├── backend/           # Express + TypeScript + Prisma (SQLite) — REST API
├── tablet-app/        # واجهة المشرف (React + Vite PWA) — Offline-first
├── web-dashboard/     # لوحة تحكم المدير العام (React + Vite)
└── README.md
```

## ⚙️ المتطلبات

- Node.js 18+ (تم البناء والتجربة على Node 24)
- لا حاجة لتثبيت أي قاعدة بيانات خارجية — يستخدم Backend قاعدة SQLite محلية (`backend/prisma/dev.db`) تُنشأ تلقائياً.

## 🚀 التشغيل السريع

افتح 3 نوافذ Terminal منفصلة:

### 1) الخادم الخلفي (Backend API — المنفذ 4000)

```bash
cd backend
npm install
npx prisma migrate dev   # ينشئ قاعدة البيانات ويطبّق المخطط + يزرع بيانات تجريبية
npm run dev               # http://localhost:4000
```

بيانات الدخول التجريبية (بعد seed):

| الفرع | الدور | PIN |
|---|---|---|
| فرع الرياض - العليا (#1) | مدير عام | `9999` |
| فرع الرياض - العليا (#1) | مشرف | `1234` |
| فرع جدة - الروضة (#2) | مشرف | `4321` |

### 2) واجهة المشرف (Tablet PWA — المنفذ 5173)

```bash
cd tablet-app
npm install
npm run dev   # http://localhost:5173
```

افتحها على جهاز لوحي (أو محاكي Chrome DevTools بوضع Tablet) لتجربة أزرار اللمس الكبيرة، الكاميرا، والميكروفون.

### 3) لوحة تحكم المدير العام (Web Dashboard — المنفذ 5174)

```bash
cd web-dashboard
npm install
npm run dev   # http://localhost:5174
```

## 🗄️ قاعدة البيانات

المخطط الكامل موجود في `backend/prisma/schema.prisma` ويطابق جميع الجداول الموصوفة في وثيقة المتطلبات (11 جدولاً أساسياً) بالإضافة إلى جدول `cleanliness_checks` لدعم جولة النظافة الإلزامية كل 4 ساعات.

> **ملاحظة تقنية:** المزود الحالي هو `sqlite` لتسهيل التشغيل المحلي بدون أي إعداد بنية تحتية. لأن Prisma لا يدعم الـ enums الأصلية على SQLite، كل الحقول التي كانت من نوع `ENUM` في وثيقة المتطلبات (الحالة، الدور، نوع السيارة...) مخزّنة هنا كـ `String` ويتم التحقق منها في طبقة التطبيق عبر `zod` (راجع `backend/src/constants/enums.ts` لكل القيم المسموحة). للانتقال إلى الإنتاج:
> 1. غيّر `provider` في `schema.prisma` إلى `postgresql` أو `mysql`.
> 2. حوّل حقول `String` المقابلة (مثل `status`, `role`, `carType`, `jobStatus`...) إلى بلوكات `enum` حقيقية في Prisma باستخدام نفس القيم من `enums.ts`.
> 3. حدّث `DATABASE_URL` في `.env`.

## 🔌 نظرة على واجهة API (Backend)

جميع المسارات تحت `/api`. المصادقة عبر `Authorization: Bearer <JWT>` (يُصدر من `/api/auth/login` أو `/api/auth/manager-login`).

| المسار | الوصف |
|---|---|
| `POST /api/auth/login` | دخول المشرف/العامل بالفرع + PIN |
| `POST /api/auth/manager-login` | دخول المدير العام (لوحة الويب) |
| `GET /api/branches`, `GET /api/branches/live` | قائمة الفروع / بطاقات حية للوحة المدير |
| `GET/POST /api/bays` | إدارة المواقف |
| `GET/POST/PATCH /api/employees` | إدارة الطاقم والصلاحيات + تفعيل/إيقاف |
| `GET /api/services`, `GET /api/services/suggest` | الخدمات وقواعد الاقتراح |
| `GET/POST/PATCH /api/job-orders` | تذاكر السيارات (متعدد الأجزاء: 4 صور إجبارية) |
| `POST /api/quality-logs`, `PATCH /api/quality-logs/:id/touch-up` | فحص الجودة + التصحيح الميداني بالمنشفة |
| `POST /api/upselling/accept`, `POST /api/upselling/reject` | البيع الإضافي |
| `POST /api/feedback` | التقييم الصوتي + تنبيه "عميل غاضب" |
| `POST /api/shift-inventory` | معالج إغلاق الوردية (3 خطوات) |
| `GET /api/cleanliness/status`, `POST /api/cleanliness/:id/complete` | جولة النظافة الإلزامية كل 4 ساعات |
| `POST /api/maintenance`, `POST /api/maintenance/:id/approve\|reject` | الصيانة والحوادث + صندوق الاعتماد اليدوي |
| `GET/POST/PATCH/DELETE /api/maintenance-schedules`, `POST /api/maintenance-schedules/:id/complete` | جدول الصيانة الوقائية الدورية للمعدات (تذكيرات تلقائية عند التأخر) |
| `GET /api/dashboard/kpis`, `GET /api/dashboard/pending-decisions` | مؤشرات الأداء وصندوق القرارات المعلقة |

الصور والتسجيلات الصوتية تُخزَّن محلياً تحت `backend/uploads/` وتُقدَّم على `http://localhost:4000/uploads/...` (بديل مبسّط للتخزين السحابي المذكور في PRD — استبدله بـ S3/Cloud Storage في الإنتاج).

## 📱 واجهة المشرف (Tablet App) — العمل دون اتصال

- **قاعدة بيانات محلية:** IndexedDB عبر `Dexie` (`tablet-app/src/lib/db.ts`) — تخزّن جلسة الدخول المؤقتة (hash محلي للـ PIN، وليس PIN فعلي) وقائمة عمليات معلقة (Outbox).
- **طابور المزامنة (Outbox):** كل عملية كتابة (سيارة جديدة، فحص جودة، بيع إضافي، تقييم صوتي، جرد وردية، بلاغ صيانة) تُحفظ أولاً محلياً، ثم يحاول محرك المزامنة (`src/lib/sync.ts`) رفعها فوراً إذا كان هناك اتصال، ويعيد المحاولة تلقائياً كل 10 ثوانٍ أو عند استعادة الاتصال (`window.addEventListener('online', ...)`).
- **حل تبعيات المزامنة:** عند إنشاء سيارة دون اتصال، تُمنح `clientUuid` مؤقت. أي عملية تالية عليها (بدء غسيل، بيع إضافي، فحص جودة...) تُرسَل بمرجع لهذا `clientUuid` ويُحل تلقائياً إلى الرقم الحقيقي للتذكرة بعد مزامنة إنشائها.
- **علامة مائية على الصور:** كل صورة تُختم بتاريخ/وقت ونص توضيحي عبر Canvas مباشرة على الجهاز قبل رفعها (`src/lib/watermark.ts`) — تحقيقاً لمتطلب الحماية القانونية.
- **قفل الخمول:** قفل تلقائي للشاشة بعد 3 دقائق من عدم التفاعل، يتطلب إعادة إدخال PIN لإلغائه.
- **تجميد جزئي للنظافة:** فحص كل 30 ثانية لحالة جولة النظافة الإلزامية؛ في حال التأخر أكثر من 15 دقيقة عن الموعد (كل 4 ساعات) تظهر شاشة تجميد تطلب تصوير الحمامات/الساحة قبل الاستمرار.
- **PWA:** يمكن "تثبيت" التطبيق على الجهاز اللوحي من المتصفح (`vite-plugin-pwa`) ليعمل بواجهة شبه أصلية وأصول مخزّنة مسبقاً (Cache-first) للعمل دون إنترنت بالكامل.

## 🖥️ لوحة تحكم المدير العام (Web Dashboard)

تطبيق ويب عادي (بدون دعم Offline، لأنه مخصص للإدارة السحابية) يغطي:
- نظرة عامة: بطاقات الفروع الحية + مؤشرات الأداء الرئيسية.
- صندوق القرارات المعلقة: اعتماد/رفض التعويضات والخصومات.
- مشغل صوتي لتقييمات العملاء + تمييز العملاء الغاضبين.
- المخزون والبيع الإضافي: مؤشر المناشف المفقودة لكل مشرف + تحليل قبول/رفض البيع الإضافي.
- إدارة الطاقم والصلاحيات: إضافة موظف، تغيير PIN، تفعيل/إيقاف فوري.

## 🧭 حالة تنفيذ المراحل الثلاث

| المرحلة | الحالة |
|---|---|
| **الأولى (MVP):** إغلاق الوردية، فحص ما قبل/بعد الغسيل، النظافة الإلزامية، لوحة التحكم الأساسية | ✅ منفذة بالكامل (تطبيق مشرف + API + قاعدة بيانات) |
| **الثانية:** البيع الإضافي، إدارة الموظفين، رضا العملاء، إدارة المخزون | ✅ قاعدة البيانات وواجهات API جاهزة بالكامل، وشاشات المشرف/المدير الأساسية منفذة (البيع الإضافي، التقييم الصوتي، جرد المخزون، إدارة الطاقم). التحليلات المتقدمة (مثل خرائط حرارية للرفض) قابلة للتوسعة فوق `/api/upselling/analytics` |
| **الثالثة:** الصيانة والأعطال، صندوق الاعتماد اليدوي، الصيانة الوقائية الدورية | ✅ قاعدة البيانات وواجهات API جاهزة، وشاشة بلاغ الأعطال في تطبيق المشرف وصندوق الاعتماد في لوحة المدير منفذة. ✅ **جديد:** جدول الصيانة الوقائية الدورية (`/api/maintenance-schedules`) مع تبويب مخصص في لوحة المدير لإضافة المعدات، تتبع تاريخ الاستحقاق القادم، وتمييز المعدات المتأخرة تلقائياً + مؤشر KPI في نظرة عامة. |

## 🔒 ملاحظات أمنية وإنتاجية قبل الإطلاق الفعلي

- غيّر `JWT_SECRET` في `backend/.env` إلى قيمة عشوائية قوية.
- استبدل تخزين الملفات المحلي (`backend/uploads`) بخدمة تخزين سحابي حقيقي (S3/GCS) خلف CDN.
- فعّل HTTPS ووسّع مهلة صلاحية الجلسة (JWT) حسب سياسة الأمان الخاصة بك.
- أضف Rate limiting على `/api/auth/*` لمنع تخمين PIN.
- انتقل من SQLite إلى PostgreSQL/MySQL للخادم المركزي عند الانتقال للإنتاج متعدد الفروع.
